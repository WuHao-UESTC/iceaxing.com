# 首页改版方案：攀登冰山 2.0

> 状态：待确认方案
>
> 范围：仅首页视觉与信息架构，不改变文章、分类、项目的 URL 规则和 Sanity 内容模型。

## 1. 改版目标

首页继续使用“从 3200m 走向 6200m”的四段路线，但每一段都应该像一次真实的登山动作，而不是一组并列卡片：

- **山脚营地**：进入站点、阅读精选派送，强调“出发”。
- **技术冰脊**：技术栈与项目是“攀爬路线”，强调能力、难度和进度。
- **雪原横渡**：生活切片是沿途观察，强调片段、节奏和空间感。
- **高山夜营**：碎碎念与站内入口是夜间地图，强调停留、回望和下一站。

本次改版解决三个问题：

1. 背景图从写实摄影改为统一的漫画插画语言，并为明暗主题提供独立版本。
2. 删除博客日历，释放首屏和山脚营地的垂直空间。
3. 技术栈、生活切片、高山夜营使用三种不同的版式语法，减少“卡片堆叠感”。

## 2. 视觉方向

### 2.1 核心语言

采用“高山探险手册 + 当代漫画分镜”的方向：

- 清晰的墨线轮廓、平涂色块、少量网点/纸张颗粒。
- 山脊、等高线、冰裂纹、路标、绳索、冰镐、营灯作为结构元素，而非装饰贴纸。
- 背景插画承担叙事，前景内容保持高可读性；不使用写实照片滤镜或模糊大图。
- 保留现有中英文字体组合：中文以 `Noto Serif SC` 为叙事字体，英文标题使用 `Cormorant Garamond`，坐标与状态使用 `JetBrains Mono`。
- 圆角保持克制，主要使用直角、细边框和不规则切角；重复内容用行、节点、轨迹组织，而不是浮动卡片。

### 2.2 建议色彩

深色主题：

- 冰夜底色：`#071522`
- 深岩蓝：`#12344A`
- 冰面高光：`#B7D8E6`
- 营灯黄：`#F4C95D`
- 绳索红棕：`#A66A53`

浅色主题：

- 雪面底色：`#EAF4F7`
- 阴影蓝：`#B9D4DF`
- 墨线蓝黑：`#183748`
- 路标黄：`#C78B28`
- 冰裂青：`#5E9AB0`

营灯黄是跨主题的识别色，只用于路线节点、进度、焦点和少量行动提示。

## 3. 背景图方案（4 组 × 浅色/深色）

### 3.1 资源契约

每个章节生成一组构图一致、色彩不同的图片，共 8 张：

```text
public/images/mountain-home/
  base-camp-light.webp
  base-camp-dark.webp
  technical-ridge-light.webp
  technical-ridge-dark.webp
  snowfield-light.webp
  snowfield-dark.webp
  night-camp-light.webp
  night-camp-dark.webp
```

建议尺寸：`2400 × 1600`，横向 3:2；保留中间和左侧安全区域，避免标题、路线导航与主体冲突。优先 WebP，必要时保留 JPG fallback。

主题切换通过 CSS 变量切换完整图片资源，不使用单纯的亮度/反色滤镜：

```css
.mountain-base-camp {
  background-image: var(--mountain-base-bg);
}

[data-theme="light"] .mountain-base-camp {
  --mountain-base-bg: url('/images/mountain-home/base-camp-light.webp');
}

[data-theme="dark"] .mountain-base-camp {
  --mountain-base-bg: url('/images/mountain-home/base-camp-dark.webp');
}
```

实际实现时，四个章节分别使用自己的变量；图片上方只叠加方向性可读性遮罩，不再把整张图压成一块深色背景。

### 3.2 统一生成提示词

每张图都应遵循以下共同约束：

> editorial comic-book illustration of a high-altitude ice mountain expedition, bold ink contour lines, flat gouache color blocks, subtle risograph halftone texture, graphic novel composition, crisp shapes, atmospheric but readable, no photorealism, no 3D render, no text, no logo, no UI, cinematic wide composition, leave quiet negative space for website typography

### 3.3 四个场景

| 章节 | 构图与叙事 | 浅色版本 | 深色版本 |
| --- | --- | --- | --- |
| 山脚营地 `base-camp` | 前景是小型基地、冰镐和绳圈；远景为完整冰山轮廓，人物朝右上方出发。 | 雪白、浅青、暖黄，墨线清晰，像清晨的探险手册。 | 深蓝、靛青、金黄营灯，保留山体轮廓和帐篷暖光。 |
| 技术冰脊 `technical-ridge` | 斜向上升的窄山脊贯穿画面，固定点、绳索和冰镐形成视觉路径。 | 冰蓝、岩灰、橙黄路标，强调结构和高度。 | 黑蓝、冷青、橙红警示点，增强悬崖层次但不恐怖。 |
| 雪原横渡 `snowfield` | 宽阔雪原与连续脚印/旗标形成横向节奏，人物和装备是小比例观察点。 | 近白雪面、淡蓝阴影、少量珊瑚色标记。 | 月光蓝、青灰雪面、低饱和暖色旗标，保持开阔感。 |
| 高山夜营 `night-camp` | 高处帐篷、营灯、星空与山峰剪影；帐篷周围留出可放置入口节点的负空间。 | 暮蓝底、淡紫灰山体、暖黄灯光，像傍晚漫画分镜。 | 深靛夜空、冷白星点、强暖黄营灯，突出“夜营”焦点。 |

生成时要求同一组浅/深色版本保持主体位置、透视和留白一致，避免切换主题时页面跳动。

## 4. 删除博客日历

### 4.1 用户体验变化

- 山脚营地只保留“精选派送”列表和刷新/随机入口。
- 不再通过日期点击筛选文章；精选列表始终展示 `specialPosts`。
- 删除日历面板后，山脚营地内容更集中，移动端不再出现额外一整块控件。

### 4.2 代码影响范围

- `components/home/home-dashboard.tsx`
  - 删除 `MiniCalendar` 组件。
  - 删除 `selectedDate` 状态、日期过滤逻辑和 `dateKey` helper。
  - 删除 `MiniCalendar` JSX。
  - `HomeLabels` 删除 `calendar`、`postsOnDate`、`previousMonth`、`nextMonth`、`weekDays`。
  - 精选标题固定使用 `labels.featured`。
- `components/home/static-homepage.tsx`
  - 删除三种语言中的日历相关文案。
- `lib/sanity/queries.ts`
  - 删除 `calendarPosts` 查询和返回字段；避免首页继续拉取最多 80 篇无用途文章。
- `lib/sanity/types.ts`
  - 从 `HomePayload` 删除 `calendarPosts`。
- `app/styles/components.css`
  - 删除日历相关样式和对应移动端覆盖。

这部分不影响日志页、文章页或站内搜索；日期仍保留在文章列表和文章详情中。

## 5. 技术栈：改为“技术冰脊路线图”

### 5.1 布局概念

技术栈不再是三列内容块，而是一张横向上升的路线图。左侧是海拔刻度，中间是技术节点，右侧是项目攀登记录。

```text
┌──────────────────────────────────────────────────────────────┐
│ 02 / 4200m  技术冰脊                                        │
│                                                              │
│ altitude  ────────●──────●────────●──────────────  summit   │
│                    │      │        │                         │
│ 技术节点            JS     Sanity   CSS                       │
│                     └─ category links                         │
│                                                              │
│ 项目攀登记录     [进行中项目纵向日志]     [已完成：旗标/刻痕]   │
└──────────────────────────────────────────────────────────────┘
```

### 5.2 信息表现

- **技能分类**：沿一条斜向或折线“绳索”排列，每个分类是带编号的冰锥节点；节点旁显示标题和一行简介，点击整个节点进入分类页。
- **进行中项目**：使用“攀登日志”纵向条目，项目标题、分类、创建时间和 5 格进度条沿路线排列；进度条改成短绳段/冰镐刻度，而不是普通 meter。
- **已完成项目**：作为右侧“已到达的固定点”展示，使用较小的旗标列表或山峰印章；保留刷新操作，但刷新按钮放到标题行右侧。
- **章节背景**：技术冰脊插画中的山脊方向与页面路线方向一致，内容线条应像从背景山体延伸出来。

### 5.3 版式差异

- 桌面端：路线图占主宽度，三组内容在同一个结构中错位排列；避免每组都有相同边框。
- 平板端：路线改为纵向，技能节点先出现，项目日志随后出现，已完成项目以横向滚动的固定点条带出现。
- 移动端：变成单列“绳索时间线”，每个节点拥有固定高度；项目和完成记录通过不同的标记形状区分。

### 5.4 交互

- 鼠标悬停/键盘聚焦节点时，连接线和对应项目条目高亮。
- 进度只做轻微宽度动画，尊重 `prefers-reduced-motion`。
- 不新增复杂图表库，使用现有 React 数据和 CSS 结构完成。

## 6. 生活切片：改为“雪原观察带”

### 6.1 布局概念

生活切片不使用统一尺寸卡片网格，改为一条横向“观察带”：分类是雪原上的路标，近期文章是错落的漫画分镜/照片框，形成横渡节奏。

```text
┌──────────────────────────────────────────────────────────────┐
│ 03 / 5100m  雪原横渡                                         │
│                                                              │
│  TRAIL MARKERS   生活 ── 兴趣 ── 旅行 ── 阅读                 │
│                                                              │
│       ┌───────────────┐      ┌───────┐                       │
│  ────▶│ 近期切片 01   │─────▶│ 02    │───▶ 03                │
│       │ 宽幅插画/标题 │      └───────┘                       │
│       └───────────────┘   ┌──────────────┐                   │
│                           │ 04 / 日期    │                   │
│                           └──────────────┘                   │
└──────────────────────────────────────────────────────────────┘
```

### 6.2 信息表现

- **生活分类**：保留分类链接，但从竖立卡片改成雪地路标/小旗标，沿横向路径分布；每个标记高度可以不同，避免整齐卡片墙。
- **近期文章**：第一篇作为宽幅主分镜，其他文章作为不同宽度的小分镜；图片占比高，文字只保留分类、标题、日期。
- **空状态**：显示一条未插旗的雪线和简短提示，不出现空卡片。

### 6.3 版式差异

- 桌面端：左侧路标带 + 右侧不规则分镜带，整体偏横向。
- 平板端：路标带置顶，分镜带改为两列错位布局。
- 移动端：分镜变为可横向滑动的“雪原胶卷”，首张宽幅内容完整可见，后续露出下一张边缘提示可滑动。

### 6.4 交互

- 悬停时只放大图片内容，文字和布局不跳动。
- 点击分类路标进入分类页，点击分镜进入文章；不把整个区域包成一个大链接。
- 允许刷新近期切片，保留现有 `lifeSeed` 行为。

## 7. 高山夜营：改为“星图 + 营火日志”

### 7.1 布局概念

高山夜营使用最明显的差异化布局：右侧是带等高线和星点的“营地星图”，左侧是从营火向外展开的碎碎念日志。四个站内入口围绕营灯分布，替代四张相同入口卡片。

```text
┌──────────────────────────────────────────────────────────────┐
│ 04 / 6200m  高山夜营                                         │
│                                                              │
│ 营火日志                         ·        [Profile]          │
│  FIELD NOTE 01                 ·  ✦                         │
│  标题与短文                   ✦   ◎ 营灯 ── [Log]             │
│  ────────────────                 ╲                          │
│  FIELD NOTE 02                     [Friends]   [About]        │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 7.2 信息表现

- **碎碎念**：改成营火旁的连续日志，保留 FIELD NOTE 编号、标题、摘要、日期和标签；每条之间用细线连接，像夜间记录页。
- **站内入口**：四个入口成为星图中的四个方向节点，节点文案使用现有 `entryCards` 数据；节点大小和位置固定，避免内容变化导致地图跳动。
- **星图**：背景等高线、十字坐标和星点使用 CSS 图层；营灯是唯一高亮焦点。不要新增 SVG 插画，避免与背景生成图风格冲突。

### 7.3 版式差异

- 桌面端：左 55% 日志、右 45% 星图；星图垂直居中，日志沿左边界展开。
- 平板端：先显示星图，再显示日志，入口节点改为两列。
- 移动端：星图作为顶部固定比例区域，日志在下方单列；节点文字必须在自身区域内换行，不得覆盖连线。

### 7.4 交互

- 聚焦某个入口节点时，营灯到该节点的连线变亮，节点出现轻微上移。
- 聚焦日志条目时只改变文字颜色和左侧标记，不改变整个日志列宽度。
- 夜营区域的星点动效默认低频，开启减少动效时完全静止。

## 8. 组件与样式实施建议

建议继续以 `components/home/home-dashboard.tsx` 为首页编排入口，拆分为三个语义明确的子组件，避免再增加通用卡片抽象：

- `TechnicalRidgeRoute`
- `SnowfieldJournal`
- `NightCampConstellation`

样式继续放在 `app/styles/components.css`，新增的 CSS 类使用章节前缀，避免与旧的 `.home-*` 规则互相覆盖。背景图变量统一在 `.mountain-home` 作用域内定义，主题覆盖放在 `[data-theme="light"]` 与 `[data-theme="dark"]` 下。

### 数据层最小改动

- 技术栈继续使用 `skillCategories`、`ongoingProjects`、`completedProjects`。
- 生活切片继续使用 `lifeCategories`、`lifeRecentPosts`。
- 夜营继续使用 `ramblingPosts`、`entryCards`。
- 不新增 Sanity 字段；通过 CSS 顺序、索引和现有 `progress` 字段完成布局差异。

## 9. 实施顺序

1. 先生成并确认 8 张漫画背景图，检查构图安全区和浅/深主题一致性。
2. 删除日历组件、状态、查询和类型字段，跑 `npm run lint` 与 `npm run build`。
3. 实现技术冰脊路线图，优先桌面端，再补时间线式移动端。
4. 实现雪原观察带，重点验证横向胶卷在移动端不会造成页面整体横向溢出。
5. 实现星图 + 营火日志，补键盘焦点、减少动效和空数据状态。
6. 用桌面 `1440px`、平板 `834px`、移动 `390px` 检查四个章节的标题、按钮、图片和连线是否重叠。

## 10. 验收标准

- 首页不再出现博客日历，也不会继续请求 `calendarPosts`。
- 四个章节各有一张漫画背景图；浅色/深色主题切换时使用独立资源，构图不跳变。
- 技术栈能直观看出“路线、节点、进度、已完成固定点”的关系。
- 生活切片呈现“观察带/分镜”结构，不是等宽卡片网格。
- 高山夜营呈现“星图/营火日志”结构，四个入口与营灯有明确空间关系。
- 三个区域的布局语法明显不同，但共享海拔、路线、等高线和营灯这套主题语言。
- 所有链接、刷新按钮、键盘焦点和移动端交互可用；减少动效设置下不出现持续动画。
- `npm run lint`、`npm run build` 通过；无新的 TypeScript 错误或 CSS 横向溢出。

## 11. 待确认的默认决策

如果没有额外指定，后续实现按以下默认值推进：

- 背景图采用“墨线 + 平涂 + 轻网点”的漫画插画，不做像素画或日式萌系角色风格。
- 图片格式优先 WebP，保留现有文件名语义并增加 `-light` / `-dark` 后缀。
- 保留右侧桌面路线导航；移动端继续固定在底部，但改成更轻量的四个圆点。
- 保留现有随机刷新能力，只移除日期筛选能力。
- 不引入 Three.js、图表库或新的 Sanity 字段，先用现有数据和 CSS 完成第一版。
