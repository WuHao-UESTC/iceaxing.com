# 在线工具板块设计与维护说明

> 文档状态：已实施，作为后续维护基线  
> 适用项目：iceaxing.com  
> 首个工具：番茄钟（Pomodoro）  
> 最后更新：2026-09-25

## 1. 目标与边界

在线工具板块用于承载可直接在浏览器中使用的小工具。它属于网站的一部分，但不是博客内容分类，也不依赖文章、项目或合集的数据模型。

首版目标：

- 在桌面端和移动端导航中新增“在线工具”入口。
- 新增工具中心页，让访问者一眼看出当前有哪些工具、用途是什么、是否可用。
- 新增第一个工具“番茄钟”，支持专注时长、休息时长、循环周期设置；空闲时显示访问者本地时间。
- 延续网站现有蓝白 / 黑金双主题、衬线标题、等宽辅助信息和雪线意象，同时采用区别于博客列表的工作台式布局。
- 保持中文、英文、德文三种语言的现有路由和内容能力。

首版明确不做：

- 不在首页增加工具展示、入口卡片或新的首页章节。
- 不把工具作为 Sanity 分类、项目或文章管理。
- 不提供账号、云同步、跨设备统计或排行榜。
- 不宣称离线可用；若以后需要离线能力，应单独设计 Service Worker / PWA 策略。

## 2. 现有项目约束

实现前应保留以下既有约定：

- 项目当前使用 Next.js 16.2.6 App Router 与 React 19。
- 页面按 `app/[locale]` 组织；默认中文不带语言前缀，英文和德文分别使用 `/en`、`/de`。
- 站内链接使用 `lib/i18n/navigation.ts` 导出的本地化 `Link`。
- 页面默认为 Server Component，只有依赖计时、浏览器存储、通知和声音的交互区域使用 Client Component。
- 全站共享 `SiteHeader`、`SiteFooter`、主题变量与页面过渡。
- 项目根目录 `AGENTS.md` 要求：每次实现前都要阅读 `node_modules/next/dist/docs/` 中与任务有关的当前版本文档，不能依赖旧版 Next.js 经验。

当前已有 `app/[locale]/(site)/[category]` 动态路由，因此必须把 `tools` 视为保留 slug。新增静态 `/tools` 路由可优先匹配，但 Sanity 中仍不得创建 slug 为 `tools` 的分类，以免产生语义冲突和维护混乱。

首版路由：

| 页面 | 中文 | 英文 | 德文 |

## 4. 工具中心设计

### 4.1 设计概念

工具中心采用“雪线工作台 / Basecamp Utilities”的概念。它保留现有视觉语言，但不沿用博客的封面、文章摘要、发布时间列表和阅读流。

主要差异：

- 博客页强调阅读顺序；工具中心强调快速识别与立即使用。
- 博客卡片展示内容封面；工具卡片展示功能状态、用途、类别和简化的交互预览。
- 工具中心使用更紧凑的网格、明确的状态标签和较强的按钮层级。

### 4.2 页面结构

首版工具中心由三部分组成：

1. 紧凑页头：标题“在线工具”、一句说明、当前可用工具数量。
2. 工具架：展示真实可用的工具，不使用“敬请期待”空卡填充版面。
3. 使用说明：简短说明工具在本地运行、设置如何保存，以及隐私边界。

只有一个工具时，番茄钟卡片可占据较宽区域，右侧或下方显示一个静态的 `25:00` 仪表预览和“立即使用”动作。新增工具后，自动转为两列或三列卡片网格。

工具少于 6 个时不显示搜索和分类筛选，避免制造无效控件；达到 6 个后再启用客户端关键词筛选和类别筛选。筛选只针对已加载的静态目录，不应让工具中心变成动态渲染页面。

### 4.3 视觉规则

- 沿用 `--color-*`、`--font-*`、`--line`、`--background` 等现有主题变量，不为单个工具写死一套独立颜色。
- 浅色主题以冰川蓝、雪白和细蓝灰边线为主；深色主题以黑灰、暖金和低亮度面板为主。
- 大标题使用现有衬线字体，计时数字、状态、快捷键和参数使用等宽字体，正文使用现有 UI 字体。
- 装饰图形使用轻量 SVG / CSS 等高线、路径刻度或高度标记，不使用与现有风格无关的通用插图库。
- 卡片用细边框、低对比面板和小圆角；避免高饱和渐变、大面积玻璃拟态和厚重阴影。
- 动画只用于状态切换、进度变化和轻微入场；遵守 `prefers-reduced-motion`。

### 4.4 工具目录数据

工具目录应由一个代码内的静态注册表统一维护，而不是在页面中重复写卡片。每个工具至少包含：

- 稳定且全小写的 `slug`。
- 标题、简介和关键词的翻译键。
- 类别，例如专注、时间、文本、开发。
- 状态，例如稳定版或测试版。
- 图标名称或内部图标标识。
- 排序权重。
- 是否在工具中心公开展示。

路由是否真实存在仍由文件系统决定。注册表用于展示和发现，不能把不存在的路由标记为可用。

## 5. 番茄钟设计

### 5.1 核心体验

番茄钟页面采用“攀登节奏仪”的视觉概念：主计时区像高度表，环形或弧形进度代表当前阶段，循环节点像一段登山路线。它应保持安静、专注，不加入与计时无关的游戏化信息。

桌面端采用主次双栏：

- 主区：大号时间、当前阶段、进度、主要操作按钮、当前循环位置。
- 侧栏：时长设置、行为设置、今日会话摘要和快捷键提示。

移动端改为单列，主计时区优先，设置收纳在其下方；关键的开始、暂停、继续和重置操作始终容易触达。

### 5.2 状态模型

界面至少区分以下状态：

| 状态 | 主显示 | 可用操作 |
| --- | --- | --- |
| 空闲 | 当前本地时间、日期、时区 | 开始专注、修改设置 |
| 专注中 | 专注剩余时间、进度、循环序号 | 暂停、结束本轮 |
| 已暂停 | 冻结的剩余时间 | 继续、重置 |
| 休息中 | 休息剩余时间、下一轮提示 | 暂停、跳过休息 |
| 阶段完成 | 完成提示和下一阶段 | 开始下一阶段、返回时钟 |
| 全部完成 | 本次循环摘要 | 再来一组、返回时钟 |

“不用的时候显示当前时间”具体定义为：没有正在运行或暂停的会话时，主显示区域展示访问者设备的本地时间；初次进入、主动重置和完成后返回空闲态都适用。服务端不要直接输出具体时刻，以免服务器时区与客户端时区造成 hydration 不一致；客户端挂载前显示稳定占位。

### 5.3 设置项与默认值

| 设置 | 默认值 | 建议范围 | 说明 |
| --- | ---: | ---: | --- |
| 专注时长 | 25 分钟 | 1–120 分钟 | 每轮专注时间 |
| 短休息 | 5 分钟 | 1–30 分钟 | 普通循环后的休息 |
| 循环周期 | 4 轮 | 1–12 轮 | 一组包含的专注轮数 |
| 长休息 | 15 分钟 | 1–60 分钟 | 完成整组后的可选休息 |
| 自动开始下一阶段 | 关闭 | 开 / 关 | 默认关闭，避免页面擅自开始计时 |
| 提示音 | 开启 | 开 / 关 | 使用简短、低刺激声音 |
| 桌面通知 | 关闭 | 开 / 关 | 仅在用户主动开启时申请权限 |

设置值需要在输入时校验并给出明确错误，不得只依赖 HTML 输入限制。会改变当前运行会话的设置应在下一阶段生效，避免计时过程中突然跳时。

### 5.4 计时准确性

计时不能简单地每秒将剩余值减一。开始或继续时记录绝对截止时间，并用 `截止时间 - Date.now()` 计算剩余时间；定时器只负责刷新界面。这样浏览器标签页进入后台并被限频后，返回页面仍能得到正确时间。

建议规则：

- 剩余时间向上取整到秒，显示不应提前归零。
- 暂停时保存精确剩余毫秒数；继续时基于该值生成新的截止时间。
- 标签页恢复可见、窗口重新获得焦点时立即校正一次。
- 页面重开后，如果保存的阶段已经过期，进入“阶段完成”状态，等待用户确认，不自动跨过多个专注 / 休息阶段。
- 系统时间被手动大幅调整时，以新的系统时间校正，并通过状态提示避免悄悄改变会话。

### 5.5 本地保存与隐私

首版仅使用浏览器本地存储：

- 保存计时设置、声音偏好和自动开始偏好。
- 保存当前会话的阶段、循环位置、截止时间或暂停剩余时间，以支持刷新恢复。
- 保存当天已完成的专注轮数和总专注分钟数；只做轻量摘要，不建立长期行为画像。
- 数据不上传到 Sanity，不发送到服务器，也不用于订阅系统。

本地存储键统一加 `iceaxing-tools-` 前缀，并包含数据版本号。读取时必须校验结构；无效或旧版本数据回退到默认值。结构升级时提供迁移或安全丢弃策略，不能让旧数据导致页面崩溃。

### 5.6 提醒、快捷键与页面信息

- 声音由用户的开始操作解锁；如果浏览器阻止播放，计时功能仍应正常完成。
- 通知权限只能由明确的“开启桌面通知”操作触发，不在页面载入时弹出权限请求。
- 页面处于后台且阶段结束时才优先使用系统通知；前台使用页面内提示和声音。
- 计时运行时可把页面标题更新为“剩余时间 · 当前阶段 · iceaxing”，离开工具页时恢复。
- 主计时台支持原生全屏显示；全屏中保留阶段、进度、主要操作和循环路线，支持按钮或 `Escape` 退出，不支持该 API 时隐藏入口。
- 可提供空格键开始 / 暂停、`R` 重置，但光标位于输入框、选择框或按钮时不得拦截按键。
- 若加入屏幕常亮功能，必须做能力检测、由用户主动开启，并在不可用时安静降级；它不是首版验收的必需项。

## 6. 技术实现原则

### 6.1 Server / Client 边界

- 工具中心页、番茄钟页面壳、页面标题、说明文字和 metadata 保持为 Server Component。
- 只有番茄钟交互主体使用 Client Component。
- 浏览器时间、`localStorage`、Notification、AudioContext、Page Visibility 等 API 只能在客户端生命周期或事件中访问。
- 不为计时器引入全站状态库；使用局部 reducer / 状态机即可。
- 把阶段推进、设置校验和剩余时间计算写成无浏览器依赖的纯函数，便于测试。

### 6.2 国际化

需要在 `zh.json`、`en.json`、`de.json` 同步增加：

- `nav.tools`。
- `tools` 命名空间：工具中心标题、简介、类别、状态、卡片动作、隐私说明。
- `pomodoro` 命名空间：阶段、按钮、设置、校验、通知、统计和 metadata 文案。

时间与日期使用 `Intl.DateTimeFormat` 和当前 locale，不手写中英文日期顺序。计时数字保留易读的 `HH:MM` 或 `MM:SS` 形式，不做语言化替换。

任何一个语言缺少关键翻译都不算完成。新增文案时避免把显示文本散落在组件内。

### 6.3 SEO 与站点发现

- 工具中心和番茄钟各自提供本地化 title、description、canonical 与 hreflang alternates。
- 在 `app/sitemap.xml/route.ts` 的静态路径中加入 `/tools` 和 `/tools/pomodoro`，为三种语言生成 URL。
- 工具中心可使用 `CollectionPage` 语义，番茄钟可使用合适的 `WebApplication` / `SoftwareApplication` JSON-LD；只描述真实功能，不写虚构评分和下载量。
- 工具页面默认允许索引。以后上线实验性或不完整工具时，可单独决定是否 `noindex`。

### 6.4 样式隔离

- 工具样式集中放在独立的 `tools.css` 并由全局样式入口导入，类名使用 `tools-`、`tool-` 或 `pomodoro-` 前缀。
- 复用全站设计 token，不覆盖根级主题变量。
- 不修改博客 `.listing-*` 或 `.blog-*` 样式来迁就工具页面。
- 在 320px 宽度、200% 缩放和低视口高度下，主要操作与设置仍可访问，页面不得横向溢出。

## 7. 新增工具的维护流程

每次新增工具按以下顺序执行：

1. 明确工具解决的问题、输入、输出、隐私边界以及是否需要服务端能力。
2. 选择稳定 slug；确认不与静态页面、语言前缀或 Sanity 分类 slug 冲突。
3. 在工具注册表新增目录项，并补齐三种语言的标题、描述、关键词和状态。
4. 创建明确的静态工具路由；不要在首版使用一个可以接收任意 slug 的通用工具页面。
5. 默认使用 Server Component 页面壳，只把必要交互下沉到 Client Component。
6. 复用工具区布局与设计 token；新增视觉规则时优先扩展工具区公共样式，而不是复制整套样式。
7. 添加 metadata、canonical、hreflang、站点地图地址和必要的结构化数据。
8. 更新本文件的“工具清单”和变更记录。
9. 完成自动检查与浏览器验收后再把工具状态改为稳定版。

需要后端、文件上传、剪贴板、摄像头、麦克风、地理位置或通知权限的工具，应额外记录：数据是否离开设备、权限请求触发点、拒绝权限时的降级行为、文件大小限制和错误恢复方式。

## 9. 验收清单

### 导航与页面

- 桌面导航和移动菜单都能进入工具中心，键盘焦点清晰。
- 工具中心能直接看到全部已公开工具及其用途。
- 首页视觉和内容未发生变化。
- `/tools` 不会落入 `[category]` 的 Sanity 分类页。
- 中文、英文、德文路径、切换语言与浏览器返回均正常。

### 番茄钟功能

- 空闲时显示本地时间、日期和时区，不出现 hydration 警告。
- 专注、短休息、长休息、暂停、继续、跳过、重置和整组完成状态正确。
- 自定义时长和 1–12 个循环均能正确推进。
- 切换标签页、让标签页后台停留后，剩余时间仍准确。
- 刷新页面可恢复有效会话；过期会话进入完成确认，不连续跳过多个阶段。
- 设置和当日摘要可保存；损坏的本地数据不会导致白屏。
- 通知被拒绝、声音播放失败或相关 API 不可用时，核心计时仍可使用。

### 视觉与可访问性

- 浅色和深色主题均具有足够对比度，状态不只依靠颜色表达。
- 320、390、768、1024、1440px 宽度无横向滚动和控件遮挡。
- 200% 缩放与低高度窗口下仍能操作。
- 所有表单控件有可见标签，错误提示与控件关联。
- 动态阶段变化通过克制的 `aria-live` 提示，不每秒朗读倒计时。
- 键盘可以完成主要操作；快捷键不会干扰表单输入。
- 全屏进入、按钮退出和 `Escape` 退出后，计时状态与页面布局均保持连续。
- `prefers-reduced-motion` 下没有持续旋转、脉冲或不必要的位移动画。

### 工程检查

- 阅读本地当前版本 Next.js 相关文档后再实现。
- ESLint、TypeScript 和生产构建通过。
- 浏览器控制台无错误和 hydration 警告。
- sitemap 包含三种语言的工具中心和番茄钟地址。
- 不提交 `.next`、临时截图或构建产物的无关变化。

## 10. 建议实施顺序

1. 建立工具注册表、三语言文案和导航入口。
2. 完成工具中心静态布局、响应式样式、metadata 与 sitemap。
3. 先实现番茄钟纯状态模型和时间计算，再连接界面。
4. 加入本地保存、刷新恢复、声音与通知降级。
5. 完成主题、响应式、可访问性和后台计时验收。
6. 最后统一文案与微动效，并把工具清单状态更新为稳定版。
